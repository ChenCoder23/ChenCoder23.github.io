# 操作系统的运行环境

> 本章回答一个核心问题：**操作系统怎样在硬件之上运行，并安全、高效地为应用程序提供服务？**

## 学习目标

学完本节，应能说明：

- 为什么 CPU 要区分用户态和内核态，以及哪些操作属于特权操作；
- 外部中断、内部异常和系统调用分别由谁触发、是否同步、如何返回；
- 一次系统调用或 I/O 请求从用户程序到内核再回到用户态的完整路径；
- 时钟中断、I/O 中断和 DMA 如何支撑调度与设备管理；
- 408 选择题、判断题中最容易混淆的术语和表述。

## 一、先建立整体图景

计算机可以粗略分成三层：

1. **硬件**：CPU、内存、I/O 控制器、磁盘、网卡、时钟等。
补充 IO控制器具体是什么
2. **操作系统内核**：直接管理硬件，提供进程、内存、文件、设备等服务。
3. **应用程序**：浏览器、编辑器、游戏等，通过操作系统使用硬件。

应用程序不能随意操作硬件，否则一个程序就可能关掉整台机器、读取别的程序的数据。因此 CPU 提供了**运行模式**和**中断机制**，操作系统再通过**系统调用**开放受控的服务入口。

>补充:我在学习时对IO控制器的概念一直比较模仿,这里再介绍一下

I/O 控制器（Input/Output Controller，输入/输出控制器）可以先把它理解成：
CPU 和各种外部设备之间的“中间管家”。
比如你的电脑有键盘、鼠标、硬盘、网卡、显示器、USB 设备。CPU 不应该直接处理这些设备的各种电气细节，所以中间需要一个专门的硬件——I/O 控制器。



## 二、处理器的运行模式：用户态与内核态

### 1. 两种状态

现代 CPU 通常至少区分：

- **用户态（目态）**：运行普通应用程序，权限较低。
- **内核态（管态、核心态）**：运行操作系统内核，权限较高。

CPU 的状态寄存器（如 PSW 中的模式位）记录当前模式。计算机启动并进入内核后通常处于内核态；操作系统加载应用程序运行时切换到用户态。(其实PSW就是通过一个二进制为来表示的,0代表内核态,1代表用户态)

### 2. 特权指令

只能在内核态执行的指令称为**特权指令**，典型包括：

- 开、关中断；
- 停机；
- 设置页表、段表或地址边界寄存器；
- 修改时钟/定时器；
- 直接执行 I/O 指令；
- 修改内存保护和 CPU 控制寄存器。

用户态程序执行特权指令时，硬件会拒绝执行并产生**保护异常**，进入内核处理。

### 3. 模式切换不等于进程切换

- **模式切换**：同一个进程在用户态和内核态之间切换，进程身份和地址空间通常不变。
- **进程切换（上下文切换）**：从进程 A 换到进程 B，需要保存和恢复 PCB、寄存器等上下文。

例如，进程调用 read() 时会发生用户态→内核态→用户态的模式切换；如果数据尚未到达，进程还可能阻塞，调度器再把 CPU 分给另一个进程，这才涉及进程切换。

## 三、中断与异常：让 CPU 及时处理事件

### 1. 基本概念

**中断（广义）**是 CPU 暂停当前程序，转去处理某个事件，处理完再返回。

按事件来源分为：

| 类型 | 产生原因 | 是否同步 | 例子 |
|---|---|---|---|
| 外部中断（狭义中断） | CPU 外部设备或时钟发出信号 | 异步，与当前指令无关 | 时钟中断、磁盘 I/O 完成、网卡收到数据、掉电 |
| 内部异常（异常/例外） | 当前执行的指令引起 | 同步，与当前指令有关 | 除零、非法指令、缺页、越权访问、断点、系统调用 |

记忆：**外中断异步，内异常同步。**

### 2. 异常的常见细分

- **Fault（故障）**：通常可以修复，处理后重新执行当前指令。典型是缺页异常。
- **Trap（陷阱）**：有意触发或在指令执行后报告，通常返回下一条指令。系统调用、断点常归入此类。
- **Abort（终止）**：严重且不可恢复，通常终止当前程序。

不同教材对“中断、异常、陷阱”的术语边界可能略有差异，考试应抓住“外部异步、内部同步”和返回地址这两个核心。

### 3. 中断响应流程

典型流程如下：

1. CPU 在合适的指令边界检查中断/异常。
2. 硬件保存最小现场，通常包括 PC（断点地址）和 PSW。
3. CPU 切换到内核态，使用内核栈，并按需要屏蔽中断。
4. 根据中断号/异常号查询**中断向量表**，得到处理程序入口地址。
5. 内核处理程序再保存通用寄存器等完整现场。
6. 处理事件：记录时钟、搬运 I/O 数据、处理缺页、唤醒进程等。
7. 恢复现场，执行中断返回指令，回到原程序或调度后的程序。

**中断向量是入口地址表，不是中断处理程序代码本身。**

### 4. 中断与调度的关系

中断发生后不一定立即切换进程：

- 时钟中断可能更新时间、扣减时间片，并触发抢占调度；
- I/O 中断可能唤醒等待磁盘的进程，调度器再决定是否切换；
- 某些中断处理完直接返回原进程。

因此：**中断 ≠ 进程切换**。

## 四、系统调用：应用程序进入内核的受控入口


### 1. 什么是系统调用


![Snipaste_2026-09-13_21-22-13](/images/uploads/1789305747250-Snipaste_2026-09-13_21-22-13.png)

系统调用是应用程序请求操作系统服务的编程接口，常见类别有：

- **进程管理**：创建、结束、等待进程；
- **文件管理**：打开、读、写、关闭文件；
- **设备管理**：申请、释放、读写设备；
- **内存管理**：申请空间、映射页面；
- **通信与信息维护**：进程通信、获取时间和系统信息。

应用程序不能直接执行磁盘控制器指令，而是调用 open()、read()、write() 等接口，请求内核代办。

### 2. 一次系统调用的典型过程

以 read(fd, buf, n) 为例：

1. 应用程序准备系统调用号和参数（寄存器、栈或内存）。
2. 执行 syscall、svc 或传统 trap 等特殊指令。
3. CPU 产生同步异常，自动切换到内核态并跳到统一入口。
4. 内核根据系统调用号分派到对应处理函数。
5. 内核检查参数和权限，访问文件系统和设备。
6. 若数据未准备好，进程可能阻塞；数据到达后由 I/O 中断唤醒。
7. 内核设置返回值/错误码，执行返回指令回到用户态。

> 再举一个write()的例子

 ```c
#include <unistd.h>

int main() {
    const char *msg = "Hello\n";

    write(1, msg, 6);

    return 0;
}
```
>这是一段简单的C语言代码,效果是工作台输出 "hello",和我们学过的 Printf() 类似,而实际上 printf() 就是由 write() 封装而来



系统调用是**受控的模式切换**，用户程序不能通过修改 PSW 或普通跳转指令“自行提权”。

### 3. 库函数不一定是系统调用

- printf() 可能先在用户态缓冲，必要时才调用 write()；
- strlen()、排序函数等纯计算库函数完全在用户态执行；
- 一个库函数可能封装多个系统调用，一个系统调用也可能有多个库函数封装。

所以：**函数调用 ≠ 系统调用；库函数 ≠ 系统调用。**

## 五、I/O 运行环境：程序如何与设备协作

### 1. 程序控制 I/O

CPU 反复查询设备状态，设备准备好后再传输数据。

- 优点：实现简单；
- 缺点：CPU 忙等，效率低。

### 2. 中断驱动 I/O

CPU 启动设备后先去执行其他任务，设备完成后发出 I/O 中断，内核再处理结果。

这也是“设备主动通知 CPU”的方式，适合等待时间较长的设备。

### 3. DMA（直接存储器访问）

大块数据传输时，DMA 控制器可以在设备和内存之间直接搬运数据，CPU 只负责初始化和结束处理，减少逐字节参与。

典型流程：

1. CPU 设置源地址、目标地址、长度和方向；
2. DMA 控制器执行批量传输；
3. 传输完成后产生中断；
4. 内核检查结果并唤醒等待进程。

## 六、时钟与启动：操作系统如何获得“运行机会”

### 1. 时钟中断

硬件定时器周期性产生时钟中断，操作系统借此：

- 维护系统时间；
- 统计进程运行时间；
- 实现时间片轮转；
- 触发抢占式调度；
- 检查睡眠和超时事件。

没有周期性时钟中断，用户程序可能长期占用 CPU，操作系统难以公平调度。

### 2. 计算机启动的大致过程

1. 加电后，CPU 从固化的启动地址执行 BIOS/UEFI。
2. 固件完成基本硬件检测，寻找启动设备。
3. 启动加载程序（bootloader）把操作系统内核装入内存。
4. 内核建立页表、中断向量表、设备驱动和进程管理结构。
5. 内核创建初始用户进程，启动登录界面或服务。
6. 普通应用以用户态运行，通过系统调用使用内核服务。

## 七、常考知识点清单

### 必须掌握

- 用户态/内核态的目的、区别和切换条件；
- 特权指令的含义和典型例子；
- 外部中断与内部异常的来源、同步性；
- 中断响应流程：保存现场→切换状态→查向量→执行处理程序→恢复返回；
- 中断向量表的作用；
- Fault、Trap、Abort 的区别及返回位置；
- 系统调用的作用、分类和执行过程；
- 库函数、普通函数调用与系统调用的区别；
- 时钟中断对时间片和抢占调度的作用；
- 程序控制 I/O、中断驱动 I/O、DMA 的特点。

### 高频判断

- 缺页是内部异常，不是外部 I/O 中断；
- 系统调用通常通过陷阱/特殊指令进入内核；
- 用户态不能执行关中断、修改页表等特权操作；
- 中断处理程序运行在内核态；
- 发生中断不必然发生进程切换；
- 硬件首先保存的现场通常不等于完整现场；
- 中断向量是地址表，不是处理代码；
- 关中断通常只能屏蔽可屏蔽中断，不能屏蔽不可屏蔽中断（NMI）。

## 八、易错点与辨析

| 易错说法 | 正确理解 |
|---|---|
| “进入内核态就一定换了进程” | 可能只是同一进程的模式切换 |
| “所有中断都会导致调度” | 调度由内核根据具体情况决定 |
| “缺页是磁盘发出的中断” | 缺页由当前指令访问不在内存的页引起，是同步异常；随后内核可能发起磁盘 I/O |
| “系统调用就是普通函数调用” | 系统调用需要特殊指令和硬件模式切换 |
| “中断向量就是中断处理程序” | 向量通常是指向处理程序的入口地址 |
| “用户程序可以用指令修改 PSW 进入内核态” | 特权状态只能由受控的中断/异常入口改变 |
| “CPU 保存了所有寄存器后才进入处理程序” | 硬件通常先保存 PC、PSW 等最小现场，其余由软件保存 |
| “关中断可以屏蔽一切中断” | 通常只影响可屏蔽中断，NMI 仍可响应 |
| “调用 printf 一定发生系统调用” | 可能仅修改用户态缓冲区，刷新时才调用系统调用 |

## 九、用一个完整例子串起来

用户在文本编辑器中按下“保存”：

1. 键盘控制器产生 I/O 中断，内核读取按键并把字符放入输入缓冲区。
2. 编辑器仍在用户态运行，发现需要保存文件，于是调用 open() 和 write()。
3. 特殊指令触发系统调用，CPU 切换到内核态。
4. 内核检查文件权限，组织磁盘 I/O 请求，进程可能进入阻塞状态。
5. CPU 调度其他进程运行；磁盘完成后发出 I/O 中断。
6. 内核处理中断、唤醒编辑器，编辑器恢复运行并取得返回值。
7. 系统调用返回，CPU 回到编辑器用户态。

这个例子同时体现了：用户态/内核态、系统调用、I/O 中断、阻塞唤醒、时钟调度和可能发生的进程切换。

## 十、考前速记

- **权限**：用户态低，内核态高；特权指令只能内核态执行。
- **来源**：外部中断异步，内部异常同步。
- **返回**：Fault 回当前，Trap 回下一条；具体以题目约定为准。
- **入口**：系统调用靠特殊指令，中断/异常靠向量表分派。
- **关系**：中断不等于切换，模式切换不等于进程切换。
- **I/O**：程序控制会忙等，中断驱动让设备通知，DMA 负责大块搬运。
- **调度**：时钟中断提供时间片和抢占机会。

## 十一、自测题

1. 用户态程序执行“关中断”指令会发生什么？为什么？
2. 缺页异常和磁盘 I/O 中断分别属于哪一类事件？二者可能如何先后出现？
3. printf()、write()、strlen() 中，哪些一定是系统调用？
4. 中断发生后，为什么不一定发生进程切换？
5. DMA 为什么能降低 CPU 在大块 I/O 中的负担？

> 建议答题时始终按“事件来源 → 是否同步 → CPU 如何切换 → 内核如何处理 → 是否需要调度”的顺序分析。
