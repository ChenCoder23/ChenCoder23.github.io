你平时在浏览器里敲个地址、点个按钮，后端到底发生了什么？其实没那么玄乎，就是数据在一群「分工不同的家伙」之间传了一圈。

一句话概括：**请求从浏览器出发，经过 Controller、Service、Mapper，最后到 MySQL，拿到数据后再原路返回。**

![一次 HTTP 请求的旅程](/images/diagrams/request-flow.svg)

## 每个角色都在干嘛

- **Controller（控制层）**：像公司前台。你打电话进来，他先接听，看看你参数对不对、有没有权限，然后把活儿转给后面的人。
- **Service（业务层）**：真正干活的人。比如「下单」「登录」这些业务规则，都写在这里。
- **Mapper / DAO（数据层）**：像仓库管理员。他只负责一件事——去数据库取东西、存东西，不掺和业务逻辑。
- **MySQL（数据库）**：仓库本体，数据真正躺在里面。

## 为什么要分这么多层

说白了就是**各干各的，谁也别越界**。哪天你想把 MySQL 换成别的数据库，只改数据层那一小块就行，业务代码不用动。这也叫「高内聚、低耦合」——听着绕，其实就是「自己的事自己管，别都搅在一起」。

## 小结

记住这条链路就够入门了：

> 浏览器 → Controller → Service → Mapper → MySQL，再一层层返回。

后面你写接口，基本都是在往这几层里填代码。
